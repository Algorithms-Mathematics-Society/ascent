was sent and no deployment was performed.

Concurrency coverage includes 40 simultaneous distinct reminders sharing a campus
IP, duplicate submissions, exact rate-limit admission, uncapped and capped
registration, competing admin decisions, atomic bulk decisions and both outboxes.
The shared-IP reminder admission transaction is separate from saving the reminder
and email job so unrelated record writes do not extend its lock. A failed save
still consumes its request slot; retrying does not create duplicate reminder jobs.

Email-specific coverage uses actual Firestore transactions and a mocked Resend
SDK: 20 competing delivery attempts cause one provider call, missing credentials
leave jobs pending, retries preserve the provider key and payload after ambiguous
failures, crashed leases recover, expired idempotency windows require review,
definite rejections can retry the following day, reminders are scheduled for the
opening instant, superseded unattempted decisions are skipped, and legacy
reminders are backfilled once across concurrent workers.

The browser check included `/admin/email` on mobile and desktop and verified its
process button is disabled while sending is unconfigured. The email SDK remains
server-side. Lighthouse was not rerun for this email addition; the earlier
[performance audit](2026-09-14.md) records the measured baseline.

Production deliverability, domain verification, provider quotas and cron execution
remain to be verified when credentials are configured. See the
[email setup runbook](../email-setup.md).
